## 3. Arm C G4 で何が起きたか（採点器の誤作動ではない）

`data/reports/w10/armC_G4_duplicate_grid.png`（上段：C′ の正解、中段：C G1、下段：C G4。index 0 / 10 / 25 / 45）。

- index 4 以降、**Target の複製がスタート位置（u ≈ 297, v ≈ 346）に残り続ける**。もう 1 個は control どおりに上昇して右へ動く
- index 0〜19 は、tracker が「動く方」を最大成分として拾っているので、誤差は 2〜8 px と小さい
- index 20 以降は、動く方が遮蔽板に隠れて面積が小さくなり、**静止した複製のほうが最大成分になる**。誤差が 90〜290 px に跳ぶ
- tracker は 2 個の成分を正しく検出しており、T_coherence が FAIL を出しているのも正しい

§12 の State coherence の「複製」に当たる、**生成そのものの破綻**である。§37.6 の tracker failure（検出 0）の定義には当たらない。
採点器は設計どおりに動いた。

### 5.2 破綻の頻度そのものが arm の違いである可能性

T_control が 47 px を超えた生成（S1 の G1〜G4）は、A 0 / 4、B 0 / 4、**C 1 / 4**。
Arm C は精度の差に加えて、**まれに Target を複製する**という別の種類の弱さを持つのかもしれない。
ただし n = 4 で 1 本なので、偶然と区別できない。言えるのは「観測された」までである。
