## §13.x Arm C（Object-Aware 3D Tracking）の点仕様

### 確定値

| 項目 | 旧（ラウンド1-2） | **新（ラウンド4）** | 変更理由 |
|---|---|---|---|
| 点の半径 | 3 px | **6 px** | 3pxは静止画でも色誤差14で余裕が無く、動くと崩壊する |
| 色の付け方 | 局所最大分離パレット12色 | 変更なし | — |
| 分離割当半径 | 24 px | 変更なし | — |
| 密度 | 0.3 点 / 空間潜在セル | **未確定**（測定時は全画面480点） | 対象物体上の必要点数が未定のため保留 |
| **V_max** | 未測定 | **≥ 17 px/frame** | 17まで検証済み。上限は未測定 |

### V_max の定義と条件

```
V_max = VAE往復後も点の色が識別可能な、スクリーン空間での最大速度
測定条件: 一様並進 / 視差なし / ラップアラウンド / 832×480 / 49フレーム / bf16
判定基準: 色誤差 ≤ 24（= 局所最小色間距離 48.1 の半分）
```

**「≥ 17」は下限。** 17より速い条件は測っていない。半径6の色誤差は
V=17で11.3と上限24の半分以下なので、さらに余裕がある可能性は高い。

### Blender アニメーション設計への制約

| 半径 | V_max | 49フレームで動ける距離 | 画面幅832pxに対して |
|---|---|---|---|
| 3 px | 3 px/frame | 144 px | 17% |
| **6 px** | **≥ 17 px/frame** | **≥ 816 px** | **ほぼ横断可** |

半径6を採用することで、当初想定していた「16fpsで3秒＝画面横断」の
物体運動が設計可能になった。§10 の編集区間（frame 12-23 で停止/減速）とも矛盾しない。

**ただし条件付き。** 測定は一様並進（画面全体が同じ方向に同じ速さでスライド）
で行った。実シーンではカメラ運動により視差が生じ、手前と奥で速度が異なる。
この条件は未検証なので、シーン設計時は V_max に安全率をかける
（例: 0.7倍 → 12 px/frame）ことを推奨する。

### 未確定として残す項目

1. **半径6での点数上限。** 480点（占有12.8%）でしか測っていない。
   点を増やすと Arm C の空間解像度は上がるが、重なりが増え、
   Arm B（密なWorld-XYZ場）との差が曖昧になる。
   → Blender のシーンを作り、対象物体に何点乗るかを見てから決める。
2. **V_max の真の上限。** 17より上は未測定。
3. **視差ありの条件。** 一様並進より厳しくなる可能性がある。

## §13.y 評価指標の変更 — identity から色誤差へ

### 変更内容

```
旧: identity復元率（近傍照合）を主指標とする
新: 色誤差（正解位置における8bit平均絶対誤差）を主指標とする
    identity復元率は補助指標として併記する
```

### 変更理由

identity復元率は**点の密度に強く依存する**ことが実測で判明した。

| 条件 | 半径 | 点数 | 平均近傍数 | identity(V=17) | 色誤差(V=17) |
|---|---|---|---|---|---|
| A | 3 px | 1872 | 6.8 | 49.3% | 29.77 |
| B | 3 px | 480 | 2.4 | **85.7%** | 23.73 |
| C | 6 px | 480 | 2.4 | 93.8% | **11.30** |

A と B は**半径も速度も同一で、点数だけが違う。** それだけで identity が
36ポイント動く。紛らわしい相手が減っただけで、点の品質は変わっていない。

```
identity = 点の品質 × 近傍の紛らわしさ  ← 混合物
色誤差   = 点の品質そのもの              ← 分離済み
```

Arm A / B / C は表現の密度が本質的に異なるため、identity で横比較すると
「点が疎な表現ほど高スコア」というバイアスが入る。RQ1（適応コスト）の
評価でこれを使うと結論が歪む。

### 併記のルール

identity を報告する場合は、必ず次を添える。

- 点数と平均近傍数
- 同一条件の V=0 ベースライン（絶対値ではなく落差で読む）

## §13.z 実測で確定した VAE の仕様

| 項目 | 値 | 備考 |
|---|---|---|
| 潜在形状（通常） | `[1, 16, 13, 60, 104]` | 49フレーム → 13潜在 |
| 潜在形状（framewise） | `[1, 16, 49, 60, 104]` | 時間圧縮なし |
| フレーム数の関係 | `out_T = T × 4 − 3` | 1 + 12×4 = 49 を裏付け |
| Peak VRAM（往復） | **4,481 MiB** | tilingなし / bf16 / 49f / 832×480 |
| 1往復の所要 | 3.1 s（RTX PRO 6000）/ 7.4 s（RTX 3090） | |
| `tiled` の既定値 | **False** | 明示指定は不要だが安全のため渡す |

**Phase 0.0 の VAE 作業に大容量GPUは不要。** LoRA学習の29.4GBとは別物で、
VAE往復は4.5GBで足りる。RTX 3090クラスで完結する。
大容量GPU（PRO 6000）が必要になるのは Main Training 以降。

### DiffSynth 2.0.18 の API 注意点

```python
# 引数の型が2つのモードで違う
vae.encode([video[0]], device=device, tiled=False)   # リスト。要素は (C,T,H,W)
vae.encode_framewise(video, device=device)           # テンソル。(B,C,T,H,W)

# mean / std は nn.Module のバッファではないので .to() で移動しない
vae.mean = vae.mean.to(device=device, dtype=dtype)
vae.std  = vae.std.to(device=device, dtype=dtype)
vae.scale = [vae.mean, 1.0 / vae.std]

# 画素値の範囲は [-1, 1]（preprocess_video の既定 min_value=-1, max_value=1）
```
